> 文档类型：Implementation-Ready Product & Technical Specification  
> 产品名称：转个格式  
> 平台：Android  
> 文档版本：v1.0  
> 当前阶段：第一版开发规格  
> 默认语言：简体中文

---

## 1. 项目概述

“转个格式”是一款面向普通用户的 Android 本地文件格式转换工具，主要处理图片、视频和音频。

产品核心不是提供复杂的专业编码参数，而是让用户通过统一、简单、可理解的设置完成文件转换。用户不需要先判断文件属于图片、视频还是音频，也不需要理解码率、CRF、采样率、编码器 Profile 等概念。

应用自动识别文件类型，并将文件按以下类别分组：

- 图片
- 视频
- 音频

每一类文件使用相同的参数卡片和交互方式。界面只向用户暴露少量统一概念：

- 输出格式
- 质量
- 尺寸（仅适用于图片和视频）
- 开始转换

底层根据文件类别、输出格式和设备能力，将这些统一选项转换成不同的实际编码参数。

---

## 2. 产品目标

### 2.1 核心目标

1. 用户打开应用后可以立即选择文件，不需要先选择转换类型。
2. 自动识别图片、视频和音频，并按类型分组。
3. 使用统一、简洁的参数界面完成批量转换。
4. 转换过程完全在本地完成，默认不上传任何文件。
5. 支持后台转换、进度显示、取消和结果分享。
6. 界面符合现代 Android 设计习惯。
7. 第一版支持简体中文和英文。
8. 支持浅色、深色、跟随系统，以及强调色选择。
9. 默认强调色为蓝色。
10. 将底层转换引擎与 UI 完全隔离，便于后续替换或扩展。

### 2.2 产品定位

“转个格式”不是专业转码器，也不是视频编辑器。

它的定位是：

> 一个简单、可靠、好看的本地格式转换工具。

### 2.3 关键产品原则

- 不要求用户理解专业术语。
- 用户目标优先于编码参数。
- 尽可能自动选择推荐参数。
- 不显示当前设备无法执行的格式或选项。
- 不因为追求功能数量而破坏主流程。
- 不依赖单一转换引擎完成所有任务。
- 所有文件操作优先围绕 Android `Uri` 设计，而不是依赖绝对路径。
- 默认不覆盖、不删除原文件。

## 3. 第一版范围

### 3.1 第一版必须实现

#### 文件输入

- 从系统文件选择器选择一个或多个文件。
- 支持混合选择图片、视频和音频。
- 支持通过 Android 分享菜单将文件发送到“转个格式”。
- 自动识别文件类型。
- 自动过滤无法识别或暂不支持的文件。
- 展示无法处理文件及原因。

#### 图片转换

第一版目标输入格式：

- JPG / JPEG
- PNG
- WebP
- BMP
- GIF（第一版可仅转换静态首帧）
- HEIC / HEIF（设备支持时）

第一版目标输出格式：

- JPG
- PNG
- WebP

第一版参数：

- 输出格式
- 质量
- 尺寸

#### 视频转换

第一版目标输入：

- 设备能够解码的常见视频格式
- MP4
- MOV
- MKV
- WebM 等常见容器中的受支持轨道

第一版目标输出：

- MP4
- WebM（设备和引擎支持时）

第一版参数：

- 输出格式
- 质量
- 尺寸

第一版附加能力：

- 保留音频
- 视频静音
- 从视频提取音频，可在后续小版本加入

#### 音频转换

第一版目标输入：

- MP3
- AAC / M4A
- WAV
- FLAC
- Ogg
- Opus
- 设备或兼容引擎能够识别的其他常见格式

第一版目标输出：

- MP3
- AAC / M4A
- WAV
- FLAC
- Ogg / Opus（取决于引擎支持）

第一版参数：

- 输出格式
- 质量

#### 任务与结果

- 批量转换。
- 显示总体进度。
- 显示单文件进度和状态。
- 取消单个任务。
- 取消全部任务。
- 转换失败后显示原因。
- 支持后台运行。
- 转换完成通知。
- 打开结果文件。
- 分享结果文件。
- 查看文件所在位置。
- 再次转换。
- 显示转换历史。

#### 基础设置

- 语言：简体中文、英文、跟随系统。
- 主题：浅色、深色、跟随系统。
- 强调色选择。
- 默认强调色：蓝色。
- 默认保存位置。
- 文件重名处理。
- 默认质量。
- 是否保留元数据。
- 转换完成通知。
- 自动清理临时文件。

### 3.2 第一版不包含

- 完整视频编辑时间线。
- 视频拼接。
- 多段裁剪。
- 复杂滤镜。
- 字幕编辑。
- 字幕烧录。
- 多音轨专业管理。
- 专业色彩管理。
- AI 超分辨率或画质增强。
- 云端转换。
- 账号系统。
- 跨设备同步。
- 在线文件下载。
- 任意 FFmpeg 命令输入。
- 面向专业用户的完整编码器参数面板。

## 4. 用户流程

### 4.1 主流程

```text
打开应用
→ 选择文件
→ 自动识别并按类型分组
→ 设置输出格式、质量和尺寸
→ 可继续添加文件
→ 开始转换
→ 查看总体和单文件进度
→ 转换完成
→ 打开、分享或查看保存位置
```

### 4.2 首页

首页应尽量简洁，主要视觉中心是“选择文件”。

页面包含：

- 应用名称或简洁标题。
- 主按钮：选择文件。
- 辅助说明：支持图片、视频和音频，可一次选择多个文件。
- 最近任务入口。
- 设置入口。
- 当前存在未完成任务时，显示任务状态卡片。

首页不提供以下三个并列主入口：

- 图片转换
- 视频转换
- 音频转换

原因：应用已经支持自动识别，重复分类会增加操作步骤。

### 4.3 文件参数页面

选择文件后进入统一参数页面。

顶部显示：

- 已选择文件总数。
- 文件总大小。
- 添加更多文件。
- 清空全部文件。

文件按以下类型分组：

- 视频
- 图片
- 音频

每一组使用相同风格的卡片。

示例：

```text
视频 · 3 个
输出格式    MP4
质量        高
尺寸        1080P

图片 · 12 个
输出格式    WebP
质量        高
尺寸        保持原始

音频 · 5 个
输出格式    MP3
质量        高
```

页面底部固定主要按钮：

- 开始转换

### 4.4 多类型混合文件

当用户选择多种文件时：

- 自动分为视频、图片和音频三组。
- 每组独立设置输出格式。
- 每组独立设置质量。
- 视频和图片独立设置尺寸。
- 音频不显示尺寸。
- 没有某类文件时，不显示对应分组。
- 每组可折叠，但默认全部保持简洁可见。
- 文件较多时，组内文件列表默认只展示前几个，并提供“查看全部”。

### 4.5 转换页面

开始转换后进入转换状态页面。

页面顶部显示：

- 正在处理或已完成。
- 已完成数量 / 总数量。
- 总体进度。
- 当前文件名称。
- 当前阶段，例如“读取文件”“正在转换”“正在保存”。

文件列表显示：

- 文件名。
- 原格式 → 目标格式。
- 状态。
- 单文件进度。
- 取消按钮。
- 失败原因。
- 重试按钮。

任务状态包括：

- 等待中
- 准备中
- 转换中
- 正在保存
- 已完成
- 已取消
- 失败

### 4.6 完成页面

完成后不使用“下载”作为主要文案，因为文件已经位于本地设备。

主要操作：

- 打开
- 分享
- 查看位置
- 再次转换

次要操作：

- 删除转换结果
- 删除原文件

“删除原文件”必须：

- 默认关闭。
- 需要明确确认。
- 不与转换完成自动绑定。

## 5. 参数系统

## 5.1 统一参数模型

UI 层只使用以下统一概念：

- 输出格式
- 质量
- 尺寸

底层转换引擎负责将其映射成不同媒体类型的真实参数。

UI 不直接保存或显示：

- CRF
- 视频码率
- 音频码率
- 采样率
- 编码器 Profile
- GOP
- 像素格式
- FFmpeg 命令
- MediaCodec 名称

### 5.2 质量选项

统一质量档位：

- 最佳
- 高
- 标准
- 省空间

不使用“中”“低”作为主要用户文案。

统一语义定义：

| 档位 | 用户理解 |
|---|---|
| 最佳 | 尽量接近原文件质量，文件可能较大 |
| 高 | 肉眼差异较小，适度压缩 |
| 标准 | 质量和体积平衡 |
| 省空间 | 优先减小文件体积 |

### 5.3 图片质量映射

初始建议映射：

| 档位 | JPEG / 有损 WebP 质量 |
|---|---:|
| 最佳 | 95 |
| 高 | 85 |
| 标准 | 75 |
| 省空间 | 60 |

规则：

- PNG 为无损格式，不显示质量选项，或将其解释为压缩速度而不是画质。
- 无损 WebP 不显示画质档位。
- 不允许因为选择“最佳”而将低质量源文件放大或虚假提升画质。
- 默认质量为“高”。

### 5.4 视频质量映射

视频质量档位映射为一组内部参数，而不是单一数字。

内部考虑因素：

- 输出分辨率。
- 输出编码器。
- 帧率。
- 原视频码率。
- 原视频复杂度。
- 是否使用硬件编码。
- 当前设备支持能力。

初始策略：

- 最佳：接近源文件视觉质量，设置较高目标码率。
- 高：保持清晰度，适度压缩。
- 标准：体积与画质平衡。
- 省空间：降低目标码率，必要时提示用户降低分辨率。

规则：

- 不允许输出码率无意义地高于源文件。
- 不允许默认将低分辨率视频放大到更高分辨率。
- 默认尺寸为“保持原始”。
- 默认质量为“高”。

### 5.5 音频质量映射

以 MP3 为例：

| 档位 | 初始目标码率 |
|---|---:|
| 最佳 | 320 kbps |
| 高 | 256 kbps |
| 标准 | 192 kbps |
| 省空间 | 128 kbps |

不同格式使用不同映射：

- AAC 在相同听感下可以使用不同码率。
- Opus 使用适合其编码特性的码率。
- WAV 不显示质量选项。
- FLAC 不以音质档位改变音质，可隐藏质量或将其解释为压缩级别。
- 不允许将低码率源音频转换成高码率后宣称画质或音质得到提升。

### 5.6 尺寸选项

#### 视频尺寸

- 保持原始
- 4K
- 2K
- 1080P
- 720P
- 480P

规则：

- 输出选项不得超过设备可处理能力。
- 默认不显示明显高于原分辨率的尺寸，或者允许选择但明确提示“不会提升清晰度”。
- 竖屏视频保持原始方向和宽高比。
- “1080P”等档位以短边或标准视频高度进行内部解释，并保持比例。

#### 图片尺寸

推荐按照最长边表示：

- 保持原始
- 3840 像素
- 2560 像素
- 1920 像素
- 1280 像素
- 自定义

规则：

- 默认保持宽高比。
- 自定义仅提供宽度和高度输入。
- 可提供“保持比例”开关，默认开启。
- 第一版可以暂不提供复杂裁剪模式。
- 默认尺寸为“保持原始”。

#### 音频

音频不显示尺寸设置。

### 5.7 动态参数显示

根据输出格式动态显示有效选项：

- PNG：隐藏质量。
- WAV：隐藏质量。
- FLAC：可隐藏质量，或显示压缩程度。
- 不支持尺寸变化的格式：隐藏尺寸。
- 当前设备无法生成的格式：不显示或标记不可用并解释原因。
- 参数隐藏和出现应使用平滑动画，避免页面跳动突兀。

## 6. 界面与交互设计

### 6.1 设计体系

使用：

- Kotlin
- Jetpack Compose
- Material 3
- Edge-to-edge
- Material Icons 或统一的矢量图标库
- Android 原生系统文件选择器
- Android 系统分享面板
- Android 通知系统

整体风格：

- 简洁。
- 原生。
- 现代。
- 留白充足。
- 层级明确。
- 避免复杂装饰。
- 文件和任务状态优先。

### 6.2 导航结构

推荐底部导航：

- 转换
- 历史
- 设置

“转换”页面同时承担：

- 首页。
- 文件选择。
- 当前参数设置入口。
- 未完成任务入口。

### 6.3 统一参数组件

输出格式、质量和尺寸使用统一的设置行组件。

推荐表现：

```text
输出格式                        MP4 >
质量                              高 >
尺寸                          1080P >
```

点击后使用以下任一种方式展示选项：

- Material 3 Modal Bottom Sheet
- 简洁选择对话框

优先使用 Bottom Sheet，便于单手操作和展示选项说明。

### 6.4 文件卡片

文件卡片显示：

- 缩略图或类型图标。
- 文件名。
- 格式。
- 文件大小。
- 图片尺寸，或音视频时长。
- 删除按钮。

视频和图片可生成缩略图。

音频使用统一音频图标，后续可增加封面读取。

### 6.5 空状态

首页空状态文案示例：

中文：

```text
选择要转换的文件
支持图片、视频和音频，可一次选择多个文件
```

英文：

```text
Choose files to convert
Images, videos, and audio are supported
```

### 6.6 加载与反馈

- 文件分析期间显示进度或骨架屏。
- 大量文件不可长时间无反馈。
- 任何失败必须显示可理解原因。
- 不直接向普通用户展示底层异常堆栈。
- 可在“查看详情”中提供技术错误信息，便于反馈问题。

## 7. 多语言设计

### 7.1 第一版语言

支持：

- 简体中文
- 英文
- 跟随系统

默认行为：

- 系统语言为简体中文时使用中文。
- 系统语言为其他语言时使用英文。
- 用户手动选择后覆盖系统语言。

### 7.2 实现要求

- 所有用户可见文本必须来自字符串资源。
- 禁止在 Compose 页面中硬编码可见文案。
- 使用 Android 标准资源体系。
- 中文资源：`values-zh-rCN/strings.xml`
- 英文资源：`values/strings.xml`
- 用户语言设置保存在 DataStore。
- 语言切换后界面立即刷新，尽量不要求用户重启应用。

### 7.3 文案要求

- 中文使用简洁自然表达。
- 英文不逐字直译，应符合工具类应用习惯。
- 文件格式名保持大写英文缩写。
- 参数档位在不同语言中语义一致。

对应关系：

| 中文 | 英文 |
|---|---|
| 最佳 | Best |
| 高 | High |
| 标准 | Standard |
| 省空间 | Smaller file |
| 保持原始 | Original |
| 开始转换 | Convert |
| 添加更多文件 | Add more files |
| 查看位置 | Show in folder |
| 跟随系统 | Follow system |

## 8. 主题与强调色

### 8.1 主题模式

支持：

- 跟随系统
- 浅色
- 深色

默认：

- 跟随系统

主题设置使用 DataStore 持久化。

### 8.2 强调色

默认强调色：

- 蓝色

第一版提供预设颜色：

- 蓝色
- 青色
- 绿色
- 紫色
- 粉色
- 橙色
- 红色

可选增加：

- 跟随系统动态配色

默认策略：

- 默认使用应用蓝色主题，而不是自动启用动态色。
- 用户可以在设置中主动切换为系统动态配色。
- Android 版本不支持动态配色时自动回退到所选预设色。

### 8.3 强调色作用范围

强调色用于：

- 主要按钮。
- 选中状态。
- 进度指示器。
- 开关。
- 标签。
- 当前导航项。
- 少量强调图标。

强调色不应大面积铺满背景。

### 8.4 无障碍要求

- 浅色和深色主题下均满足基本对比度。
- 强调色不能作为唯一状态信息。
- 错误、成功、警告还需结合图标和文字。
- 支持系统字体缩放。
- 主要点击区域不小于 Android 建议尺寸。

## 9. 技术架构

### 9.1 推荐技术栈

| 模块 | 技术 |
|---|---|
| 语言 | Kotlin |
| UI | Jetpack Compose + Material 3 |
| 状态管理 | ViewModel + StateFlow |
| 导航 | Navigation Compose |
| 持久化设置 | DataStore |
| 本地数据库 | Room |
| 文件选择 | Storage Access Framework / Photo Picker |
| 文件保存 | MediaStore / ACTION_CREATE_DOCUMENT |
| 常用图片转换 | ImageDecoder / Bitmap / Bitmap.compress |
| HEIF / AVIF | AndroidX HeifWriter / AvifWriter，设备支持时 |
| 常用音视频转换 | Jetpack Media3 Transformer |
| 扩展格式兼容 | 隔离的 FFmpeg 模块 |
| 后台长任务 | Foreground Service |
| 辅助任务 | WorkManager |
| 依赖注入 | Hilt 或 Koin，推荐 Hilt |
| 日志 | 统一 Logger 抽象 |

### 9.2 Android 版本

建议：

```text
minSdk = 26
```

理由：

- 降低老旧系统兼容成本。
- 满足现代文件访问、通知和媒体能力需求。
- 仍覆盖大量 Android 设备。
- 有利于 AI 辅助开发时减少条件分支。

## 10. 转换引擎设计

### 10.1 多引擎原则

不使用单一引擎处理所有文件。

推荐：

- 图片常用格式：Android 原生图片能力。
- 常用视频和音频：Media3 Transformer。
- MP3、FLAC、WAV、特殊容器和兼容需求：FFmpeg 兼容层。
- 根据设备能力、输入格式和目标格式自动选择引擎。

### 10.2 引擎接口

```kotlin
interface ConversionEngine {
    fun supports(request: ConversionRequest): Boolean

    suspend fun convert(
        request: ConversionRequest,
        onProgress: (ConversionProgress) -> Unit
    ): ConversionResult

    suspend fun cancel(taskId: String)
}
```

### 10.3 引擎实现

```text
NativeImageEngine
Media3Engine
FfmpegEngine
```

### 10.4 调度器

```kotlin
interface ConversionEngineSelector {
    fun select(request: ConversionRequest): ConversionEngine
}
```

示例：

```text
JPG → WebP
→ NativeImageEngine

H.265 MP4 → H.264 MP4
→ Media3Engine

FLAC → MP3
→ FfmpegEngine

视频 → MP3
→ FfmpegEngine 或可用的专用音频链路
```

### 10.5 FFmpeg 隔离要求

- UI 和业务层禁止直接拼接 FFmpeg 命令。
- 所有 FFmpeg 参数只能由 `engine-ffmpeg` 内部生成。
- FFmpeg 依赖必须可独立替换。
- 正式发布前确认 16 KB 页面支持。
- 正式发布前审查 LGPL / GPL 许可证。
- 只编译或引入必要的编码器和解码器。
- 记录实际构建配置和版本。
- 不将未经维护验证的社区 AAR 作为不可替换核心。

## 12. 文件访问与保存

### 12.1 输入设计

所有输入优先保存为 `Uri`。

使用：

- `ACTION_OPEN_DOCUMENT`
- Photo Picker
- Android 分享 Intent
- `ContentResolver`

不将文件绝对路径作为核心数据。

### 12.2 临时文件策略

当底层引擎只能接受文件路径时：

```text
读取源 Uri
→ 复制到应用缓存目录
→ 执行转换
→ 写入目标 Uri 或 MediaStore
→ 验证输出
→ 删除临时文件
```

要求：

- 转换前检查剩余空间。
- 临时文件命名避免冲突。
- 应用异常退出后可清理残留。
- 大文件复制必须显示准备状态。
- 不在主线程进行文件复制。

### 12.3 输出位置

默认保存目录建议：

```text
Download/转个格式
```

或根据媒体类型写入相应 MediaStore 分类。

设置中允许用户选择默认目录。

### 12.4 重名处理

支持：

- 自动添加序号，默认。
- 覆盖，需谨慎提示。
- 每次询问。

默认示例：

```text
video.mp4
video (1).mp4
video (2).mp4
```

### 12.5 原文件保护

- 默认保留原文件。
- 不自动覆盖输入文件。
- 不自动删除原文件。
- 删除原文件必须明确确认。
- 处理来自只读 Uri 的文件时不尝试修改源文件。

## 13. 后台任务

### 13.1 任务执行

长时间音视频转换使用 Foreground Service。

通知内容：

- 正在转换数量。
- 当前文件。
- 总体进度。
- 点击返回应用。
- 取消任务。

### 13.2 WorkManager 用途

WorkManager 只用于：

- 延迟重试。
- 清理缓存。
- 清理残留临时文件。
- 非实时辅助任务。

不将所有长时间转换简单实现为长时间 Worker。

### 13.3 并发策略

默认：

- 图片任务可并发 2 个。
- 音频任务默认并发 1～2 个。
- 视频任务默认串行。
- 不同时运行多个高分辨率视频编码任务。

后续可根据设备性能动态调整。

## 16. 隐私与安全

### 16.1 隐私原则

- 第一版所有转换默认在本地完成。
- 不上传文件。
- 不要求登录。
- 不收集文件内容。
- 不申请与功能无关的权限。
- 不默认申请“管理所有文件”权限。

### 16.2 权限

优先通过系统选择器授权单个文件或目录。

可能需要：

- 通知权限。
- 前台服务相关声明。
- Android 版本要求的媒体读取权限，仅在确有必要时申请。

### 16.3 日志

日志禁止记录：

- 文件正文内容。
- 完整私密路径。
- 用户媒体数据。
- 可恢复的原文件内容。

可以记录：

- 文件类型。
- 扩展名。
- 大小区间。
- 引擎名称。
- 错误代码。
- 转换耗时。
- 设备编码器能力摘要。

## 17. 错误处理

必须处理：

- 文件不存在。
- Uri 权限失效。
- 格式无法识别。
- 输入文件损坏。
- 设备没有可用编码器。
- 输出格式不支持。
- 存储空间不足。
- 临时目录不可写。
- 输出目录不可写。
- 转换引擎崩溃。
- 用户取消。
- 应用进程被系统回收。
- 转换中设备重启。
- 文件名冲突。
- 文件过大。
- 部分批量任务失败。

错误文案示例：

```text
无法读取此文件
该文件可能已被移动，或应用没有访问权限。
```

```text
设备不支持此输出格式
请选择其他格式后重试。
```

```text
存储空间不足
请释放空间后重新开始转换。
```

批量任务中某个文件失败时：

- 不应自动终止其他独立任务。
- 继续处理剩余文件。
- 最终汇总成功和失败数量。

## 18. 性能要求

### 18.1 基础要求

- 文件分析不阻塞主线程。
- 参数页面在选择大量文件时保持可操作。
- 任务列表使用懒加载。
- 缩略图异步加载并缓存。
- 大文件不一次性读入内存。
- 图片转换避免无意义的多次解码。
- 视频转换优先使用可用硬件编码。
- 设备过热或编码器资源不足时合理降级。

### 18.2 内存

- 图片根据目标尺寸进行采样解码。
- 避免同时加载大量原始分辨率图片。
- 每个任务结束后及时释放 Bitmap、Extractor、Codec 和文件句柄。
- FFmpeg 子进程或 native 调用结束后清理资源。

### 18.3 应用体积

- FFmpeg 模块尽量裁剪。
- 按 ABI 打包或使用 App Bundle。
- 不引入重复媒体库。
- 依赖统一版本管理。

## 19. 可测试验收标准

### 19.1 文件选择

- 用户能一次选择至少 50 个混合文件。
- 应用能正确按图片、视频、音频分组。
- 不支持文件会被明确标记。
- 添加更多文件后原设置不会无故丢失。

### 19.2 参数设置

- 三类文件的参数组件视觉一致。
- 音频不显示尺寸。
- PNG 和 WAV 等不需要质量参数的格式不会展示无意义设置。
- 切换格式后参数自动更新。
- 默认质量为“高”。
- 默认尺寸为“保持原始”。

### 19.3 转换

- 转换可在应用退到后台后继续。
- 通知可显示当前进度。
- 用户可以取消单个任务。
- 用户可以取消全部任务。
- 部分任务失败不会阻止其他任务继续。
- 转换后输出文件可正常打开。
- 原文件默认保持不变。

### 19.4 多语言

- 中文系统默认显示中文。
- 非中文系统默认显示英文。
- 用户可手动切换语言。
- 切换后主要界面立即更新。
- 页面中不存在明显硬编码未翻译文本。

### 19.5 主题

- 支持浅色、深色、跟随系统。
- 默认强调色为蓝色。
- 用户选择强调色后立即生效。
- 重新启动应用后设置保留。
- 深色模式下文字和按钮清晰可见。

### 19.6 稳定性

- 转换过程中旋转屏幕不会丢失任务。
- 应用进程被系统回收后可恢复任务状态。
- 缓存清理不会删除已完成输出。
- 存储空间不足时不会产生被误认为成功的损坏文件。
- 取消任务后不会留下可见的无效输出文件。

## 23. 最终产品定义

“转个格式”的第一版应当让用户获得以下体验：

1. 打开应用。
2. 直接选择任何图片、视频或音频。
3. 应用自动识别并整理。
4. 用户只需要设置格式、质量和尺寸。
5. 点击一次开始转换。
6. 在前台或后台查看进度。
7. 完成后直接打开、分享或查看文件。

产品最重要的差异不是支持最多的专业参数，而是：

- 不需要先分类。
- 不需要理解编码知识。
- 多媒体参数视觉统一。
- 本地处理。
- 界面简洁。
- 结果可靠。
- 符合 Android 使用习惯。

底层实现必须保持可替换，UI 必须始终保持简单。
